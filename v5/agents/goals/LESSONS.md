2. "Verbatim", "byte for byte", "exact": only with a fenced block that starts with ```verify, shows the python `in` check you ran against the live source, and its output True. Otherwise write "paraphrased". The validator (V12) fails the file otherwise. (s5: paraphrased API questions claimed as byte-exact.)
3. Numbers: paste the exact command and its raw output directly under the number, in a fenced block that starts with ```repro, then a line `$ <command>`, then the raw output. 4. Never write that the operator or anyone else did something unless you can quote the file or command that proves it. (s5: "operator executed steps 0-3" was false.)
5. Drafts for posting never claim work that is not done ("I've rebased", "squashed", "completed the CLA"). Put undone work as a do-first step for the operator. (s5: FORGE replies.)
6. Edits to history: never rewrite an earlier watch or log row. Add a correction row instead. (s5: role-watch rows rewritten.)
